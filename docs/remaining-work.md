# tamiops 剩余功能核对

核对日期：2026-10-03。依据为当前源码、产品设计、架构说明和既有验收记录。此前三组审阅分别检查同步/备份、存储/网关及桌面/界面；本轮已补齐六组优先功能，并完成独立代码复核、回归与浏览器交互验收，详见[本轮验收记录](feature-completion-test.md)。

基础连接、文件管理、文件级同步、S3 转 WebDAV、备份恢复、迁移、缓存、规则和 CLI 均已有实现。**主要模块存在，不代表产品文档的全部细项已经完成。**

## 已实现但仍需验收或发布准备

- Windows/Linux：已有源代码、构建脚本和 CI 矩阵，既有记录没有平台执行结果与桌面实测。
- 真实云存储、NAS 及第三方 WebDAV 应用：已有内存/协议夹具验证，尚缺按具体产品与版本的兼容性矩阵。
- macOS：目录选择、同步、保存、缓存编辑写回、后台网关、钥匙串、单实例等已有验收；通知实际送达、托盘菜单直接点击、真正注销登录后的自动启动仍待确认。
- 性能：尚未建立大目录、大文件、大量小文件、低空闲磁盘、休眠/断网和长时间运行的完整实测基准。
- 正式分发：当前 macOS 使用 ad-hoc 签名；尚无正式签名/公证和三平台完整安装包、发布流程。此项属于发布准备，不能用“可构建”替代。

## 有意保留的协议边界与研究候选

- `PROPPATCH` 当前明确返回 501；排他 `LOCK/UNLOCK` 已有受限实现，复杂 If、共享锁和完整 WebDAV class 2 尚未实现。按目标应用需求扩展，不能笼统说“网关没做”。
- 普通 S3 多对象移动是复制后删除；通用 WebDAV 的空目录清理受能力限制。这些是服务语义边界，不能靠补一个界面按钮获得原子保证。
- 块级增量、虚拟磁盘/占位文件、多个存储统一挂载、团队权限/在线协作、移动端属于原文的远期候选，尚未实施，不计入当前桌面版本的首版缺陷。

## 需要明确的产品策略

- 冲突：当前默认暂停并等待逐项选择；“保留两份”已实现为手动动作。原产品表的“默认保留双方并生成副本”尚未成为自动策略。建议先保留当前可控行为，再确定是否增加可选自动策略。
- 重试：持久队列、重启核对与手动重试已实现；自动重试依赖剩余 pending 队列或自动观察/定时核对。纯手动任务的中断队列只重新核对和提示，不自动继续写入；需要用户执行或重试。是否提供独立自动重试规则需明确。
- 网关自启动：桌面启动不自动恢复全部入口，CLI 可显式指定启动入口；自动恢复入口是后续便利性选项，不能与应用登录启动混为一项。

上述六组功能补齐后，下一阶段应优先开展真实服务、跨平台和性能验收；效率增强、块级增量和虚拟盘继续单独排期。
