## 数据胶囊 WebDAV 真实协议测试 · 2026-10-04

用户明确授权使用 `WEBDAV_PASSWD` 测试 `https://data.cstcloud.cn/dav`。变量从交互式 zsh 继承，未写入代码、命令参数或报告。请求保持 TLS 校验，不跟随重定向；只操作带 128-bit 随机标记的临时文件，未修改已有用户文件。以下结论限于本次端点与账号，不代表其他服务或数据胶囊的 S3 接口。

| 项目 | 实测响应与内容核对 | 结论 |
| --- | --- | --- |
| OPTIONS | 200，声明 DAV 1、2 和常见 WebDAV 方法 | 声明需通过实际操作验证 |
| PROPFIND／普通 PUT、GET、DELETE | 属性 207，内容读回一致，删除后 GET 404 | 基本文件读写可用 |
| PROPFIND 与 GET 的 ETag | 同一文件返回一致的强 ETag | 本次错误并非 ETag 表示不一致 |
| 对已有文件 PUT `If-None-Match: *` | 201，旧内容确实被新内容覆盖 | 未执行仅新建条件 |
| 错误 ETag 的 PUT `If-Match` | 201，内容确实被覆盖 | 未执行版本匹配条件 |
| 错误 ETag 的 GET／DELETE `If-Match` | GET 200 返回当前内容；DELETE 204，文件随后 404 | 未执行条件读取与删除 |
| WebDAV `If` 的错误 ETag | PUT 201 覆盖；DELETE 204 删除 | 换用 DAV `If` 不能解决 |
| Range `bytes=1-6` | 200 返回完整内容，无 Content-Range | 本次不支持范围读取 |
| MOVE `Overwrite: F` 到已有目标 | 500，源和目标均未改变 | 本次拒绝，但状态码非标准，不能据此保证原子防覆盖 |
| MOVE `Overwrite: F` 到不存在的目标 | 201，源消失，目标内容一致 | 普通移动可用 |
| LOCK／UNLOCK | 200 带锁令牌／204 | 请求被接受 |
| 锁的实际保护 | 无令牌及错误令牌 PUT 均为 201 且覆盖；无令牌 DELETE 204 且文件消失 | 锁未阻止未携带正确令牌的写入与删除 |

“读写受限”由实际能力不足触发，不是密码错误，也不是普通上传不可用。上述协议诊断阶段保持安全条件写入和删除关闭；后续写入保护模式的实现和验收见下节。

两轮共使用 8 个临时路径：4 个在负向删除／移动测试中消失，4 个经内容归属与当前 ETag 复核后清理；所有路径最终 GET 404，残留为 0。测试未输出密码、锁令牌或已有文件内容。完整脱敏结果：[JSON 报告](assets/design-review/datacapsule-webdav-probe.json)。

## 数据胶囊实际任务阻塞修复 · 2026-10-04

实际任务首次上传 `.DS_Store` 时进入未决状态，后续约每 20 秒重复扫描并失败。独立随机目录对照测试确认：该服务对 `.DS_Store` 的 PUT 返回成功，但随后的 PROPFIND 与 GET 都返回 404；相同内容的普通文件可以正常写入、读取。测试文件和目录已清理。

同步现默认忽略各层级的 `.DS_Store` 文件；其他隐藏文件和同名目录不受影响。旧元数据队列与基线不再生成传输或删除操作，原未决日志与暂存仍保留。普通文件的未决写入在新预览前先做只读核对；无法确认时进入“需要处理”，停止反复自动执行，并提供“核对操作”入口。

继续实机同步时发现 HTML 下载的第二个兼容问题：服务在 gzip 传输时把强 ETag 改为弱 ETag，使原有版本检查报冲突。WebDAV 读取与范围读取现明确请求 identity 编码，保持文件原始表示与版本标识；不把弱 ETag 当作强标识放行。无 Content-Length 的下载则使用同版本元数据取得长度，并在写入本地前再次核验版本及实际字节数。

回归覆盖元数据排除、原基线/队列退役、过期计划拒绝、未决上传自动核对、不可判定记录保留、自动重试抑制、强版本的原始内容下载与无长度下载。完整竞态检测、静态检查和前端构建通过。

实机结果：17:52 完成 421 / 421 项，下载 180 个变化文件，跳过 153 项并创建 88 个目录；后续自动核对显示“没有待同步的改动”。修复后这一轮没有新增错误。旧 `.DS_Store` 的未决记录和 8 KiB 左右的暂存保留，不再阻塞其他文件；未将其伪标记为上传成功。
